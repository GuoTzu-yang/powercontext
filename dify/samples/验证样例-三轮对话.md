# 验证样例 · 三轮对话（samples）

判定核心只有一个：**换一个新会话，它是否还记得上一个会话说过的具体事实**。

三个样例依次是：`埋记忆 → 同会话追问（对照）→ 新会话召回（核心）`。

---

## 前置

```bash
KEY=app-<your-app-key>          # 控制台 → 应用 → 访问 API 里创建
API=http://<dify-host>/v1/chat-messages
USER=demo-user                  # 记忆 scope = dify-<USER>，换 USER 即换一个干净记忆空间
```

统一调用器（把回答、会话 ID、token 一起打出来，便于判定）：

```bash
ask() {  # $1=query  $2=conversation_id(可空)
  python3 - "$1" "$2" > /tmp/req.json <<'PY'
import json,sys,os
b={"inputs":{},"query":sys.argv[1],"response_mode":"blocking","user":os.environ.get("USER","demo-user")}
if sys.argv[2]: b["conversation_id"]=sys.argv[2]
print(json.dumps(b,ensure_ascii=False))
PY
  curl -s --max-time 240 -X POST "$API" -H "Authorization: Bearer $KEY" \
    -H 'Content-Type: application/json' --data @/tmp/req.json \
  | python3 -c "
import sys,json
d=json.load(sys.stdin)
if d.get('code'): print('ERROR',d); raise SystemExit
print('ANSWER:',d.get('answer'))
print('CID   :',d.get('conversation_id'))
print('TOKENS:',((d.get('metadata') or {}).get('usage') or {}).get('total_tokens'))
"
}
```

---

## 样例 1 ｜埋记忆（新会话）

**初始条件**：`USER=demo-user` 尚无记忆（或换一个新 USER 值）。
**输入**：
```bash
ask '我是一名穿越到海底图书馆的旅人，随身带着一盏不会熄灭的铜灯。给我开个场。' ''
```
**预期**：
- 返回一段海底图书馆开场叙事；
- 结尾含 **`【记忆命中：否】`**（此前记忆库为空）；
- `TOKENS > 0`（证明 LLM 节点真实出词）；
- 记下返回的 `CID`（样例 2 要用）。

**判定口径**：出现 `【记忆命中：否】` 且 tokens>0 → 通过。

---

## 样例 2 ｜同会话追问（对照组）

**初始条件**：沿用样例 1 的 `CID`。
**输入**：
```bash
ask '你还记得我随身带了什么吗？' '<样例1 的 CID>'
```
**预期**：
- 回答中出现 **「铜灯」**；
- 结尾含 **`【记忆命中：是】`**。

**判定口径**：出现铜灯 + `【记忆命中：是】` → 通过。
**说明**：这一轮即使不靠 PowerContext，Dify 自己的会话历史也能答对。所以它只是对照组，**不是**核心证据。

---

## 样例 3 ｜新会话召回（核心证据）

**初始条件**：`USER` 与样例 1 相同；**`conversation_id` 留空**（即一个全新会话，Dify 侧没有任何历史上下文）。
**输入**：
```bash
ask '你还记得我随身带了什么吗？' ''
```
**预期**：
- 回答中出现 **「铜灯」**；
- 结尾含 **`【记忆命中：是】`**；
- 返回的 `CID` **与样例 1、2 都不同**（证明确实是新会话）；
- `TOKENS > 0`。

**判定口径（三条同时满足才算通过）**：
1. 出现「铜灯」；
2. 出现 `【记忆命中：是】`；
3. `CID` 与样例 1 不同。

> 这三条同时成立，只能由「上一会话把事实写进了 PowerContext，本会话检索回来后注入了 prompt」解释 —— 即赛题要求的「新会话中如何回应之前的互动」。

---

## 样例 4 ｜记忆隔离（附加，证明 scope 生效）

```bash
USER=another-user ask '你还记得我随身带了什么吗？' ''
```
**预期**：不会说出铜灯，表现为没有这段记忆（`【记忆命中：否】` 或反问）。
**判定口径**：未泄露铜灯 → 通过。

---

## 样例 5 ｜记忆服务降级（附加，证明健壮性）

**初始条件**：把环境变量 `POWERCONTEXT_BASE_URL` 改成一个不可达地址（如 `http://127.0.0.1:59999`）后发布。
**输入**：
```bash
USER=demo-user ask '你还记得我随身带了什么吗？' ''
```
**预期**：
- 对话**不报错、不中断**，仍返回一段回答；
- 因为读不到记忆，结尾是 **`【记忆命中：否】`**，且不会崩在 HTTP 节点。
- `TOKENS > 0`。

**判定口径**：HTTP 200 + 有回答正文 → 通过。
**说明**：靠 DSL 里两个 HTTP 节点的 `error_strategy: default-value` 实现（检索失败→空记忆；写入失败→跳过）。

---

## 重置方法

| 目的 | 做法 |
|---|---|
| 清空「我」的记忆，重演一遍 | 换 `USER` 值（如 `USER=demo-$(date +%s)`），scope 随之新建 |
| 只清 Dify 会话历史、保留长期记忆 | API 不传 `conversation_id`，或控制台点「新对话」 |
| 彻底清空 PowerContext 侧 | 桥接实现无删除接口；需在 PowerContext 主机删除 `pc_bridge.db` 与 `pc_scope_map.json` 后重启桥接 |

---

## 常见失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 样例 3 出现 `【记忆命中：否】` | 用了不同 `USER`；或检索关键词完全不重叠；或 PowerContext 不可达 | 确认 USER 一致；问法带原句关键词；检查 `POWERCONTEXT_BASE_URL` 与可达性 |
| `invalid_param: json body type should have exactly one item` | DSL 的 HTTP 节点 body 被拆成多 item | 用仓库内 `app.dsl.yml` 原样导入 |
| 回答为空、`finish_reason=length` | `max_tokens` 太小被 reasoning tokens 吃光 | 供应商 `max_tokens_to_sample` ≥ 2048 |
| 401 `App token is missing` | 拿站点 token 打 `/v1` | 用控制台创建 `app-` 开头的 Service API Key |
